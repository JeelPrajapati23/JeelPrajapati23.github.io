The problem

A single generic prompt makes a poor code reviewer. It either misses real bugs or buries them in vague advice. I wanted reviews that are specific and actionable, and cheap enough to run on Groq's free tier.

There's a harder problem underneath. A reviewer that can verify its claims has to run the PR's tests, which means executing code written by whoever opened the PR. So the system is built around two real risks: running out of API budget, and running untrusted code.

How it works

  1. Receive the webhook

    GitHub sends a pull_request event. The body is HMAC-SHA256 verified, and only opened and synchronize actions continue.

  2. Deduplicate

    A Redis lock (SET NX EX 900) turns GitHub's redeliveries of the same commit into no-ops instead of second reviews.

  3. Queue and return

    The job goes to Celery and the webhook returns 202 immediately. Nothing waits on the analysis.

  4. Check budget and clone

    The worker skips drafts, checks the shared daily token budget, posts a pending status, and shallow-clones the branch with a short-lived GitHub App token.

  5. Security review

    The Security Warden looks for injection, OWASP issues, vulnerable dependencies and data leaks, using read-only MCP tools scoped to the changed files.

  6. Performance and logic review

    A second specialist looks at complexity, correctness, races and off-by-ones. It runs sequentially to stay under Groq's per-minute limit.

  7. Synthesize

    A Synthesizer merges both reports into one structured review and removes overlap.

  8. Ground or fail

    If every claim references a file the panel actually read, inline suggestions and the review are posted. Otherwise it posts a failure status.

Design
decisions

The choices that shaped the system, and why.

Quality

Specialists over one prompt

Each agent has a narrow scope and its own tools, so findings are sharper and the Synthesizer can route them into the right section.

Trust

Fail closed

A review that mentions a file nobody opened is treated as a hallucination. The PR gets a failure status, never a degraded review.

Security

Sandboxed test runs

The MCP server that runs the PR's tests uses a stripped environment and dropped privileges, so a malicious PR can't leak secrets through its test output into the model's context.

Cost

Crash-safe and budget-aware

Every agent step is checkpointed to Redis through LangGraph, so a crashed worker resumes instead of re-spending tokens. A daily budget gate skips new reviews with a neutral status when quota runs low.

Deployment

Runs with Docker Compose on an Oracle Cloud Always Free VM behind Caddy for automatic HTTPS. GitHub Actions redeploys over SSH on every push. The test suite is fully mocked and makes no live Redis, Groq or GitHub calls, with a separate opt-in integration suite.
